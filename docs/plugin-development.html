Minimal complete plugin

三个文件，一套完整契约

下面的最小插件可以直接编译。名称必须使用小写字母、数字和连字符，binary 固定命名为 dm-<name>。示例中的 SDK 路径适合本地并排开发；独立远程仓库应改用固定提交的 Git 依赖。

Explorer
  • my-plugin/
  • 　Cargo.toml
  • 　dm-plugin.toml
  • 　Cargo.lock
  • 　src/
  • 　　main.rs
[package]
name = "dm-plugin-backup"
version = "0.1.0"
edition = "2024"

[[bin]]
name = "dm-backup"
path = "src/main.rs"

[dependencies]
dm-plugin-sdk = { path = "../dameng-cli/crates/dm-plugin-sdk" }
name = "backup"
version = "0.1.0"
description = "Backup a Dameng database"
api_version = 1
use dm_plugin_sdk::{Context, Plugin, PluginResult};

struct Backup;

impl Plugin for Backup {
    fn run(&self, context: Context) -> PluginResult {
        println!("received {} arguments", context.args.len());
        // 在这里实现连接、备份或其他数据库能力。
        Ok(0)
    }
}

fn main() {
    dm_plugin_sdk::run(Backup);
}
Before publishing

交付前检查

安装过程会运行 Cargo 构建脚本，因此用户只应安装可信源码。插件仓库需要能够独立解析所有依赖。

✓
清单与 crate 版本一致避免安装时因版本不匹配被拒绝。
✓
提交 Cargo.lock远程安装始终使用 --locked 构建。
✓
入口名称符合约定backup 对应 dm-backup，不接受脚本入口。
✓
错误返回非零退出码标准输出、错误输出和退出码是公共接口。

在 dameng-cli 仓库根目录执行：

cargo generate-lockfile dm install ./my-plugin dm list dm backup --help dm uninstall backup
