# dameng-cli v0.4.2

本次带来安装预演和更完整的产物平台覆盖。

## 安装预演

`dm install <source> --check`（别名 `--dry-run`）按安装流程解析来源、校验清单、安装冲突与预编译产物：远程来源同样会下载并校验 SHA-256，本地目录会确认 `dm-<name>` 是否就绪。随后报告将要安装的插件、来源、修订、方式（首次安装或覆盖已安装插件）与可执行文件来源。它不运行 hook、不写 plugins 目录和 SQLite，失败时报出的原因与真正安装时一致，适合在 CI 里判断某个包能否安装。

```sh
dm install ./dm-plugin-backup --check
dm install https://github.com/OWNER/REPO.git --rev v1.2.0 --check
```

## 新增发布产物

宿主与内置插件新增三个平台：

- Linux ARM64 musl（`aarch64-unknown-linux-musl`），不依赖 glibc
- Linux ARMv7 GNU（`armv7-unknown-linux-gnueabihf`），保持 glibc 2.28 基线
- Windows ARM64（`aarch64-pc-windows-msvc`）

`dm self-update --target` 与配置文件的 `[update] target` 接受上述取值；`scripts/install.sh` 在 `uname -m` 为 `armv7l` 时自动选择 ARMv7 产物。插件预编译产物标签新增 `armv7-linux` 与 `aarch64-windows`，db、ssh 与 hello 模板仓库跟随同一份目标清单。GNU 目标继续检查 ELF 符号版本，并在 Debian 10 容器中启动校验（ARMv7 通过 QEMU 执行）。

## 升级

```sh
dm self-update
dm update --all
```

内置 db 与 ssh 插件本次随宿主一起发布，版本不变。数据库驱动仍不接入，`dm db test` 与 `dm db exec` 继续明确报告未实现。
